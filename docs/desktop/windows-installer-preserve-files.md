# Windows 更新：安装目录文件保留规范

## 目标

managed 覆盖更新只清理由 ZCode 发行包声明拥有的文件，安装目录中用户或其他程序放置的无关文件必须保留。安装器不得再以 `RMDir /r $INSTDIR` 作为该更新路径的清理策略；无 manifest 的历史升级不在本规范保证范围内。

## 所有权清单

- 打包阶段在 Windows 应用输出目录根部生成 `.zcode-install-manifest`，每行一个相对文件路径（反斜杠分隔、UTF-8、以换行结束）。清单只包含发行包实际携带的文件。
- 清单文件随应用包一起安装，供下一次更新时的旧卸载器读取；清单本身也属于 ZCode 所有文件，但清理遍历跳过其自引用条目，避免删除当前打开的元数据；后续安装仍会写入新清单。
- `customRemoveFiles` 仅按清单删除文件，不删除安装目录根目录或任意未列出的文件/目录。删除失败立即终止旧卸载器并保留未处理的文件，交由安装器报告失败。
- 清单路径缺失或无法读取时采用迁移安全策略：当前卸载器不删除任何安装目录文件，继续安装并保留旧版本残留。注意：首次从没有清单的旧版本升级仍会先运行旧卸载器；旧卸载器可能递归删除整个目录，本规范暂不承诺该路径的无关文件保留，需后续单独实现可回滚的 legacy 迁移。
- 清单由打包流程生成而非用户输入。实现仍拒绝绝对路径和 `..` 路径，避免恶意或损坏清单越界删除。

## 版本边界

- manifest 是 ownership cleanup 的能力标记；从首个带 manifest 的版本开始，后续版本之间的覆盖更新属于强保证范围。
- 首次从没有 manifest 的历史版本升级时，旧卸载器可能仍执行全树清理或返回原生错误文案。本规范不为该路径增加迁移备份、恢复和回滚，用户可以通过卸载重装或手动迁移完成升级。
- 版本持续前进时，只对新版本之间仍可复现的失败增加保护和诊断，不追求一次性兼容所有历史安装状态。

## 兼容和边界

- 普通卸载（无 `--updated`）继续由 electron-builder 默认流程处理；本规范只改变覆盖更新的清理阶段。
- 安装目录之外的数据目录（例如 `%USERPROFILE%\.zcode`）不在清单范围内，也不会被更新清理。
- 清单只记录文件，不主动删除空目录，因此目录中无关文件和目录结构均保留。

## 验证要求

- NSIS 隔离夹具验证：带清单时列出的旧应用文件被删除、未列出的 `user-data.txt` 保留；新卸载器清单缺失时所有旧文件保留；删除被 Windows 文件句柄阻断时返回非零并写入 `cleanup-failed` 与数字 PID。旧卸载器的 legacy 递归清理不在本阶段覆盖范围内。
- 夹具使用 electron-builder 对应的真实 NSIS 编译器；不写入真实安装目录、桌面、开始菜单或产品注册表。
- 编译夹具保持正式 header 顺序：自定义 include 先加载，`common.nsh` 的卸载器常量随后才定义；引用该常量的函数延迟到 `customHeader` 展开，禁止用夹具提前定义常量掩盖打包告警。

## 旧卸载器清理失败的恢复

新安装器必须在调用旧卸载器前、按该卸载器实际 `InstallLocation` 读取旧 manifest，
将仍存在的受管文件复制到安装目录同级的唯一备份目录。备份清单先单独保存一次；即使清单包含自身条目，遍历也不得再次排他复制它。
备份完成前不得删除旧文件；
备份失败立即停止安装，旧版保持原状。无 manifest 的历史安装继续遵守上文的 legacy 边界。

旧卸载器非零退出时，从备份恢复被删除的文件；尚存的原文件不覆盖，避免再次触碰锁定文件。
恢复时按备份中仍存在的文件校验相对路径；Windows NSIS 的路径规范化可能对已删除的目标返回空值，
不得因此跳过待恢复文件或误报恢复成功。
恢复成功后清理备份并报告清理失败；恢复失败保留备份路径并报告，不能声称旧版已完整恢复。
旧卸载器成功后移除本次清理备份。该保护针对卸载清理阶段，不承诺后续解压失败或断电的完整安装事务。

```text
旧 InstallLocation + manifest → 完整备份 → 运行旧卸载器
                                  │          ├─成功 → 删除备份 → 解压新包
                                  │          └─失败 → 补回已删文件 → 报清理失败
                                  └─失败 → 原安装目录不变，停止
```

旧卸载器重试耗尽的提示必须描述清理失败和退出码，不得用“应用无法关闭”替代；
只有真实进程检查失败才继续使用该提示。保留交互式重试/取消；取消后恢复已删除文件，静默安装默认取消。两种路径都保留安装器日志。
重试提示与取消后的最终清理失败提示均跟随安装器语言，不能在英文安装流程末尾固定显示中文。

验收使用隔离安装目录：清单中先放主程序、再放可删除文件、最后放被独占打开的文件。
运行旧卸载器后断言非零、前两项字节恢复、锁定文件不变、无关文件不变；释放句柄后重试
能够完成清理。另测备份写入失败、无 manifest、成功清理、恢复目的目录不可写及重试耗尽提示。

自引用清单回归须包含正常清理、备份后旧卸载器失败的恢复，以及成功清理后删除备份。

### 旧卸载器的清单自引用兼容

旧完整包的卸载器可能未跳过正在读取的清单自身。新安装器须先保留原清单与受管文件，成功备份后为旧卸载器原子替换一份仅移除自引用项的清单；备份或替换失败则不得开始旧卸载。清理失败时恢复原始清单字节，即使清单文件仍存在。完整包回归包含原始旧卸载器的自引用清单升级，以及失败后的原清单逐字节一致性。

本轮隔离 Windows 11 x64 完整包验证：原版 3.16.2 的清单加入自引用后，旧实现升级返回 2；修复后的完整 NSIS 安装包在自动更新清理失败时恢复 1,430 个文件及原清单字节，随后原版升级成功，再次用包含自引用的新清单覆盖安装成功。受管主程序、app.asar、工具均与完整载荷哈希一致，无关文件保留，成功后临时备份清除。安装器未配置正式签名，此结果不代表正式签名信任链、断电或解压失败回滚。
