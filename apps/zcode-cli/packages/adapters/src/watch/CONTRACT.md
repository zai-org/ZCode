# live-config-watch

完整规格见 `docs/mcp-async-tool-catalog-cache.md`「配置」与 `docs/skills-live-catalog.md`「监听范围」。

意图：打开的会话跟随磁盘配置变化，且监听数量与插件数、skill 数无关。MCP 配置源与 Skill 实时目录共用这一套，各自只写加载器。

不变量：

- 加载器每次全量读取，并登记本次读到或依赖的文件（缺失的也登记）与只看直接子目录的目录；只有结果被采纳时才 commit。
- 锚点是已存在的最近目录，缺失时只在边界之内向上找；depth 0，不监听边界之外。
- 文件事件只使条目失效，300 ms 尾部去抖后串行重读；新绑定的 watcher 就绪后再读一次。不轮询，不用超时决定状态。唯一例外是监听建立：一次绑定（逐个锚点 stat 与等 watcher 就绪/报错）共用 1 秒总截止时间（`WATCH_BIND_TIMEOUT_MS`），超时的锚点即断路、停止监听并记一条 warn；配置内容仍只由全量读盘决定。
- 同一锚点、同一身份（`dev:ino`、覆盖文件、目录列表）的 watcher 失败两次即停止监听，记一条 warn；就绪前、就绪后的报错都计数。只有经历过一次读盘提交的 watcher 收到的文件事件才清零计数。身份变化或条目重建后重新尝试。停止监听不影响 flush：仍全量重读。
- 绑定超时断路：一次绑定内同一锚点只 stat 一次，共用它的多个目标复用同一结果；stat 超时的锚点以超时标记停止监听，之后的绑定不再 stat 它；watcher 未在截止时间前就绪或报错的锚点按当前身份停止监听；截止时间过后本轮还没处理的锚点：已在监听的保留原 watcher、下一轮照常 stat，其余直接断路。断路不调度重绑、不清零，状态跟条目走，条目重建后重新尝试。
- 同一进程内 key 相同的调用方共用一个条目；复用时先 flush；最后一个 view 释放时关闭 watcher。
- 插件清单只监听提交点（安装记录、bundled 分片、配置文件）与 inline 插件文件，缓存与官方插件目录只读不监听。
