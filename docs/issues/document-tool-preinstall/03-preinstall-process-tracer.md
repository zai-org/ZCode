## What to build

打通最窄的一条完整路径：App 启动后，在独立的预装工具进程中静默准备资源，用户打开“帮助 → 预装工具”能看到真实状态。

- 新增常驻的预装工具进程（spec“术语、范围和唯一归属”）：
  - Main 在 App 启动时拉起它，App 退出时通知它收尾，并在窗口与它之间转发消息；Main 不保存预装状态。
  - 进程意外退出后由 Main 重新拉起；新进程清理临时目录、恢复状态，不自动重新下载。
  - 拉起与收尾方式参考现有 scheduler 进程。
- 启动检查：自动预装默认开启。资源已就绪时直接复用；未就绪时在后台准备一次：
  按清单下载 → 校验大小和 SHA-256 → 流式解压（保留符号链接和可执行权限，检查路径越界）→ 运行检查 → 写入安装记录。
  启动检查只核对安装记录和必需文件，不重新运行完整验证。
- 帮助菜单在“资源管理器”之后新增“预装工具”，打开方案 A 对话框的只读版本：状态标签、进度条或阶段文字。按钮和开关在 04 实现。
- 不弹出任何提示，帮助菜单项不显示状态。
- 提供仅测试可用的清单覆盖，指向受控 HTTP 服务上的小测试包；生产构建不读取这类覆盖。

### 2026-10-28 — 审查重开：初始化失败阻塞 Local Host

- 初版实现 `825e9550b0f` 和上方成功候选回放记录保留；本票因新增确认的 P1 重新置为 `in-progress`，不能以原健康目录回放代表该异常已通过。
- 代码链：Main 在创建首个 Local Host 前等待 `preinstalledToolsStartup`；bridge 只在收到 `initialized` 后结算；worker 的初始化文件操作失败会退出，bridge 又立即拉起新 worker。持续失败时等待不结束，并反复创建进程。
- 有界探针使用实际 `PreinstalledToolsInstallation.initialize()`、真实文件系统冲突和实际 bridge 源码；仅 Electron 子进程生命周期由夹具提供。空 catalog、发布根路径为普通文件时，连续三次得到 EEXIST，共观察到四次 fork，初始化 Promise 仍未结算。此结果不是完整桌面故障回放。
- 非关键旧版本／临时目录清理本已有捕获；根目录创建、设置读取或不能撤销旧记录属于不同边界。不能仅吞掉异常或直接解除屏障，否则可读但不可撤销的旧目标记录可能继续被 Agent 使用。
- 审查时提出的方案：将当前目标身份纳入固定安装记录地址，保持单环境变量、单写入 owner 和原子发布，使普通聊天启动不依赖工具初始化成功。该方案涉及 02 的路径契约、03 的启动边界和 07 的读取验证；后续已授权并按上方记录完成。
- 此节保留重开时的证据；原探针在外部交接资料 `review/startup-probe.log`。本轮完整 App 回归见上方；真实 LibreOffice 与 CDN 不由该故障回放证明。
