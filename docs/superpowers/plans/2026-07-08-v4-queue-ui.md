# V4 Queue UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring the v4 queue panel in line with the z-code-2 queue UI, make queue edit extract the item into the composer, and wire drag reorder to CLI projection state.

**Architecture:** Keep queue authority in CLI projection (`snapshot.queue.items`) and send all mutations through v4 commands. UI renders projection state only; drag reorder computes a `beforeQueueItemId` anchor and lets `TurnSteerReordered` update projection. Queue edit deletes the item through `deleteQueueItem` before filling the composer.

**Tech Stack:** React 19, TypeScript, `@dnd-kit/core`, `@dnd-kit/sortable`, lucide-react, v4 command protocol.

## Global Constraints

- Specs/docs must be updated before implementation.
- UI changes must follow `DESIGN.md`, use semantic tokens, support light/dark themes and mobile web.
- UI logs must use `packages/ui/src/logger.ts`.
- Queue state remains CLI projection authority, not renderer-local order state.
- Produce exactly three commits: visual UI, edit extraction, drag reorder.
