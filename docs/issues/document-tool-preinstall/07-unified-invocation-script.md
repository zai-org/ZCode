# 07 — 统一调用脚本与配置模板（上游插件仓库）

Status: done

## Parent

## What to build

在上游插件仓库提供一个统一调用 LibreOffice 的脚本，所有文档插件都通过它使用 LibreOffice。
这样能稳定找到正确的程序，每次调用互不干扰，也不会改动用户自己的 LibreOffice。

- 查找顺序与失败行为以 spec 01“Agent 与文档插件调用”为准：每次重读当前受管记录；受管不可用时说明原因并使用任意系统版本（含 Dev）；两者均无可用程序时走 setup.md。桌面有目标时先由用户选择等待或安装，后续仍用统一脚本。
- 受管启动或运行失败（非零退出、超时、无成功回执）在清理后用系统程序重跑一次；系统失败明确报告，取消不重跑。每次尝试使用独立配置和新回执。公式错误由既有扫描报告，不当作 LibreOffice 进程失败重跑。
- 环境变量只定位记录，不控制安装权限；没有变量的远端、Web、CLI、容器保持原安装引导。
- PDF 转换由调用方声明其私有目录内的临时产物，统一入口每次尝试前清理这些文件；系统退出成功但未产生新 PDF 时，不能接纳受管失败残留。输入和旧交付文件不在清理范围。
- 每次调用把 ZCode 专用配置模板复制到独立临时目录，通过 `-env:UserInstallation` 传入（按 file URL 编码，支持空格和中文路径），
  调用结束后删除。模板内含表格重算宏和字体替换设置。不读写用户的默认配置目录。
- Excel 重算先改为通过这个脚本运行，替换现有“把宏写进用户默认配置”的做法。
  现有做法在 Windows 上的写入位置也不对，这一点要在提交说明中写明原因。
- 系统程序不设最低版本。受管候选先实测 26.2.x 并保留兼容性和真实文档结果。
- 系统程序保留发现的绝对调用路径，符号链接解析仅用于文件检查；探测版本与实际操作均不能丢失入口名。回归使用按入口名分派的真实子进程，覆盖有效链接与失效链接跳过。
- 改动先在上游插件仓库完成；导入本仓库在 08 进行。

### 2026-10-28 — 评审修复与取消回归

- POSIX 受控启动器先退出、子进程继续持有管道时，旧清理分支会跳过进程组并提前删除调用标记和配置。公共异步入口的超时、取消用例先复现失败，再验证按本次进程组终止并等待管道关闭后清理；不以超时或固定等待作为退出证据。
- 安装记录有效但入口无执行权限或格式无效时，旧实现泄露启动错误并屏蔽有效系统程序。现在仅对进程创建失败进行回退，先释放受管使用标记；文档处理失败不重试。回归同时覆盖回退中的取消和独立配置清理。
- Python 3.9 的既有任务传播会丢失 `CancelledError` 消息，SIGTERM 因而错误返回 130。旧源码 TREE 的公共 PDF CLI 已复现；CLI owner 在事件循环外保留信号原因，公共 CLI 回归确认清理完成后返回 143。
- 上游 Python 3.12 运行回归 30/30 通过；Python 3.9 helper 回归 23 项通过、1 项因缺少 openpyxl 跳过。Windows 的启动器先退出场景仍未完整解决：`taskkill /T` 依赖存活的根进程，本次未引入 Win32 Job Object；此项是已知归属限制，不只是未执行测试。
- 真实稳定版、GUI、中文和公式验收阻塞未解除，状态与未提交要求不变。当前来源及摘要以 08 的导入记录为准。
