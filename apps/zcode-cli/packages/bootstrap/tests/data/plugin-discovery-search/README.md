# SearchPlugins 离线评估

在仓库根目录执行。两条命令都不访问网络或用户的插件存储：

```sh
pnpm exec tsx apps/zcode-cli/packages/bootstrap/tests/data/plugin-discovery-search/evaluate.mjs
pnpm exec tsx apps/zcode-cli/packages/bootstrap/tests/data/plugin-discovery-search/evaluate.mjs --performance
```

**样本。** 2026-11-02 冻结了一份实际安装的官方市场合并目录，原文件 SHA-256 为
`4f60208ff9802b1e9fa9f8b08a577e180a82ff05bccade080927bc4d059f8ca5`。68 条中排除退役插件和内部运行时宿主后，保留 66 条。
`catalog.json` 仅保留参与排名的商店信息：名称、多语言显示名和描述、分类和示例提示。未复制插件、URL、缓存路径或实际安装状态。
评估脚本统一补齐官方 ID 和未安装状态；状态不参与评分。

**标注。** `queries.tsv` 是根据目录能力预先编写的 64 条查询，包含中英文、混合查询、完整名称和自然语言任务。每条查询标注一个或多个目标插件，相关度为二值。
选定 32 条进行参数比较，另 32 条留出；其中 7 条预先标记为弱例。先冻结标签，再运行评分。不按留出结果调整参数。
Recall@10 为前十命中的标注插件占比，nDCG@10 按排名折损，多目标按理想前十归一化；表中均为各查询的等权平均。
这套数据用于回归，不代表线上查询分布。

| 集合         | 条数 | 旧 Recall@10 | BM25 Recall@10 | 旧 nDCG@10 | BM25 nDCG@10 |
| ------------ | ---: | -----------: | -------------: | ---------: | -----------: |
| 调参         |   32 |       0.4688 |         1.0000 |     0.4256 |       0.9539 |
| 留出         |   32 |       0.5000 |         1.0000 |     0.4707 |       0.9654 |
| 留出中的弱例 |    7 |       0.0000 |         1.0000 |     0.0000 |       0.9473 |

基线是原实现的名称/详情 4:1 子串规则，输入为同一批可见条目。规格参数为名称权重 4、详情权重 1、`k1=1.2`、详情 `b=0.75`。
在调参集上，名称权重 2 得 0.9654，权重 6 得 0.9476；固定权重 4，分别用 `(k1,b)=(0.8,0.5)`、`(1.6,0.9)` 均得 0.9654。这里保留规格值，不主张其为全局最优。
例如“找腾讯会议的参会报告”由未命中提升到首位，“帮我自动化操作桌面应用”由未命中提升到第二位。

**纯搜索耗时。** Node 24.14.0、macOS arm64、M4 Pro。每个规模先预热 8 次，再轮换 8 条中英文查询。
直接计时 `searchPluginCatalog`，覆盖筛选、分词、排名、必要的游标和摘要；不含目录刷新、安装状态读取或网络。
合成目录复用真实字段分布，给每条记录分配不同 ID。

|       条目 | 样本数 | p50（ms） | p95（ms） |
| ---------: | -----: | --------: | --------: |
| 66（真实） |    100 |      0.74 |      1.07 |
|      1,000 |     40 |     13.51 |     15.09 |
|     10,000 |     20 |    147.62 |    178.48 |

50 ms 验收线只适用于真实目录；脚本对该 p95 以及留出集排名执行断言。合成规模用于观察本次每次重算的成本。
