# 扩展插槽（Renderer）

设计见 `docs/plugins/extension-host.md` §6，样式见 `DESIGN.md`「Extension slots」。

- 只持三份数据的最近一份（§16.1）：静态表（Window Host，经 `onDynamicContributions` 的 `static` 消息，按 `rev` 整份替换，每次订阅的第一份直接替换）、贡献表快照（扩展进程：运行状态与动态值，按 gen/rev 整份替换，增量只更新这份快照，共用协议的 `applyContributionMessage`，`detached` 清空）、扩展进程状态（Main）。每个 `IExtensionsService` 一份 store，第一个使用者订阅、最后一个释放时退订。
- 合并只在 `domain/slotSelectors.ts`：`selectSlotEntries(sources, slot, scope)` 返回某个插槽的条目（静态条目 ⊕ 运行状态 ⊕ 按作用域合并的动态值），扩展进程停止时 target 是扩展的条目带 `hostStopped`；激活失败的扩展的条目不返回。`selectExtensionProblems` 每个插件最多一行问题；`selectStaticViews` 列出静态表的视图。新插槽只在这里加选择函数，不维护第二份条目表。
- 扩展门面只在桌面本机 Host 注册（取 base services）。Web 与手机远控没有它，插槽不显示。
- `composer.status`：用量圆环左边；只在设置了 `text` 时显示；动态值逐字段合并（会话 > 工作区 > App）。点击经 `IExtensionsService.executeCommand` 执行命令，作用域为当前会话（没有会话时为工作区）。工具栏空间不足时最先收起（`data-composer-collapse-priority="extension"`）。
- 启动页「扩展」分区：不依赖会话；`sidePane.launcher` 的视图条目点击打开扩展视图标签（动态值按工作区作用域合并）；问题行（extension 非法、不兼容、激活失败、插槽条目不可用）每个插件一行，悬停显示原因（带字段路径时显示路径）；扩展进程已停止时顶部一行「扩展已停止」带「重新加载」，视图条目照常显示，标签为「扩展已停止」，操作改为「重新加载」。没有要显示的行时分区不渲染。
- 扩展视图标签页 `extension-view`：工作区级，可见规则同 developer-tools；id 由视图全局 id 派生，同一视图只开一个。页面复用 plugin-ui 的页面原语（`hostPrimitives.ts`），后端是 `IExtensionViewsService`（扩展视图门面，与 `IExtensionsService` 同一个本机 Host、另一个频道）。实例在挂载时创建、卸载时关闭；扩展进程换代（快照 gen 变化）或侧栏目标换了会话时按新的代际与作用域重建。视图声明从静态表查。
- 打开入口 `ExtensionViewsProvider`（App 层）：启动页条目与能力 `views.open` 共用；`views.open` 的请求与回执走 `IExtensionViewsService`。它也在界面语言变化时经 `IExtensionsService.reportEnv` 报告 App 环境（能力 `env.*` 的来源）。能力 `workbench.startDraft`（§18.1 H2）的请求也到这里：交给 App 层的 `onStartDraft`（`StartExtensionDraft`：回到工作区与对话主视图，调 Root 的 `onCreateTask({ initialPrompt, targetWorkspace? })`，只预填不发送），接手后立即回执；当前工作区只读且没有指定工作区时回执失败。日志不记文字。
- 屏幕会话报告：`SessionPane` 经 `useExtensionWorkbenchPane` 登记本机工作区主对话窗格的有效会话、草稿、焦点与草稿所选模型；`workbenchReporter.ts` 用 `queueMicrotask` 合并同一轮的变化，内容没变不发。
- `nav.primary`（§16.4）：`NavPrimarySlot` 由 `ProjectSidebarNavigation` 挂在「插件市场」之后（手机远控不挂）；Shell 经侧栏 props 的 `navPrimarySlot` 给当前任务 id、`handleOpenDraftPluginUi` 与回到对话。条目按当前语言的标题排序，没有选中态；点击先回到对话主视图（右侧面板只在那里显示），view 打开扩展视图标签，surface 走 `useOpenSlotSurface`（焦点窗格的会话，没有会话时进根草稿；远程或没有沙箱时提示「不支持」）。扩展进程停止时 view 条目显示「扩展已停止」「重新加载」并改为重新加载，surface 条目照常。
- `file.viewer`（§16.5）：`useFileViewerRouter` 给 `useAppPanels` 的文件路由用，调用时读 store 的最近一份，不订阅渲染（App 级 hook 不能随贡献表增量重渲染）。查找规则在 `selectFileViewer`：文件名以扩展名结尾即匹配，每插件取第一个，多个插件取插件 id 字典序第一个（冲突每份静态表记一次 warn），扩展进程停止时 view 条目不参加。view 查看器的标签由 `buildFileViewerTab` 生成（每文件一个，带 `input`，交给视图实例的 `view.input`）。
- `composer.mention`（§16.6）：`useComposerMentionSlot` 产出每个条目一组的中性数据；`useExtensionMentionGroups` 把它映射成 `mentions/` 的面板分组（`extensions` 类别的候选项，序列化为 `insertText`），候选行组件是 `ExtensionMentionOptionContent`。`MentionPlugin` 只把它当一个候选来源。条目来自 `selectComposerMentionEntries`；每个条目只持「最近一次发出的查询（作用域 + query 与 seq）」和「最近采用的结果」，结果的 seq 不是最近一次时丢弃。面板关闭不清结果，同一个键不重发（tool 首次调用的审批会让面板关闭）。tool 条目要会话且只在本机工作区；`unsupported` 与空结果不显示；错误与「扩展已停止」在组内显示一行。命令作用域与 `composer.status` 共用 `composerCommandScope`。
- 扩展授权（§17.7）：`app/extensionGrantsStore.ts` 只持授权状态的最近一份（owner 是 Window Host 的 `IExtensionGrantsService`，每次订阅的第一份整份替换，之后只接受 rev 更大的），每个门面一份 store，引用计数订阅。`adapters/useExtensionGrants.ts`：启动页的「需要授权」行与详情页的「授权」按钮打开同一个授权对话框（复用全局 ConfirmDialog，正文是 spec 原文），确认后 `grant({ pluginId, grants: declared })`；`useRevokeExtensionGrant` 撤销；`useConfirmExtensionEnable` 在启用前调 `describeEnable`，需要时弹启用确认（读不到依据时也确认）；`useExtensionRecentActions` 在授权状态 rev 变化时重读「最近操作」，不轮询。设置页 `PluginsSection` 只对本机 user 层的启用调用启用确认。`ExtensionPermissionsSection` 是插件详情页的「权限」区块，没有授权门面（Web、手机）或插件不声明档位时不渲染。日志只记插件 id 与数量。
- 图标只从白名单渲染，其余显示通用插件图标；不接受插件提供的 HTML、SVG 或样式。
- 扩展日志标签 `extension-logs`（§16.8）：每个侧栏一个（固定 id），工作区级，可见规则同 developer-tools。缓冲的 owner 是 Main，`app/extensionLogsStore.ts` 只持投影：每个 `IExtensionsService` 一份，第一个标签挂载时先订阅 `onDynamicLogs` 再 `getLogs({})`，取快照期间的批次排队后按 seq 去重；批次首条不是 `lastSeq + 1` 时 `getLogs({ sinceSeq })` 补齐；失败时等下一批再取，不定时重试。最多 2000 条。「清空」记下 seq，跨标签开关保留。过滤、复制、时间格式在 `domain/logSelectors.ts`。入口：启动页「扩展日志」一行（静态表里有带 extension 的插件或扩展进程已停止时）与命令中心「打开扩展日志」，都经 `ExtensionViewsProvider` 的 `onOpenLogs`。
