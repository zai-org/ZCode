# 反馈窗口窄窗口布局

## 背景

桌面主窗口最小宽度是 480px。反馈窗口（`FeedbackCenter`）在窄窗口下宽度为 `100vw - 2rem`。
日文、俄文等界面语言的按钮文案比中文长一倍左右，例如底部三个按钮：

| 语言 | 我的反馈 | 取消 | 提交反馈 |
| ---- | -------- | ---- | -------- |
| 中文 | 99px     | 51px | 79px     |
| 日文 | 181px    | 91px | 161px    |

## 问题（已修复）

主窗口宽度小于约 535px 时，日文反馈窗口内容宽 501px，大于弹窗可视宽 446px：

- 初始状态右侧被裁，关闭按钮和提交按钮显示不全。
- 聚焦右侧控件后，浏览器把弹窗内容横向滚动 55px，左侧被截。

原因有两层：

1. `DialogContent` 是 `display: grid`，但没有声明列轨道，隐式列是 `auto`，
   会被子元素的最小内容宽度撑宽，超过弹窗自身的 `max-width`。
2. 反馈窗口底部三个按钮都不收缩：「取消 / 提交」按钮组是 `shrink-0`，「我的反馈」虽然写了
   `min-w-0`，但 `Button` 基础样式自带 `shrink-0`，实际也不收缩。文案变长后整行的最小宽度
   超过弹窗宽度。弹窗 `overflow: hidden` 只是隐藏溢出，聚焦时仍可被滚动。

## 规则

- `DialogContent` 的列轨道固定为 `minmax(0, 1fr)`：弹窗内容宽度永远不超过弹窗自身宽度，
  长内容由内部元素自行换行或截断，不允许把弹窗撑宽。
- 反馈窗口底部操作行在任何受支持的界面语言、480px 最小窗口宽度下都必须完整可见：
  - 「取消 / 提交」主操作不截断。
  - 「我的反馈」是次要入口，显式声明 `shrink`，空间不足时文字截断并保留图标，
    完整文案通过 `title` 提示。
- 反馈窗口在任何窗口宽度下 `scrollWidth` 必须等于 `clientWidth`，不允许出现横向滚动。

## 验收

- 日文界面、窗口宽 480px：反馈窗口标题、关闭按钮、三个底部按钮都在弹窗内；
  依次聚焦所有控件后弹窗 `scrollLeft` 保持 0。
- 中文、英文界面在 480px 和 1200px 下布局与修复前一致。
