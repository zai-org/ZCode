# 内置浏览器：设计工具

日期：2026-11-03
状态：已实现

在内置浏览器上给 HTML 设计稿 / 幻灯片做点选引用、改数值、切方案、翻页：点选的元素作为引用进输入框，用户用一句话交给 Agent；
属性面板里改的数值是明确改动，直接写回本机 HTML 源文件，Cmd/Ctrl + Z 撤销（11-05 用户反馈）。
前置能力见 [选元素带截图与自动刷新](2026-11-03-browser-element-screenshot-and-live-reload-spec.md)。

## 一、组成

## 二、通信

```text
宿主（renderer）                                         页面（guest）
  dom-ready / did-stop-loading ──signals script──▶  读 data-zcode-design、:root CSS 变量、data-variant、section.slide
  运行时需要时 dom-ready ─────install script─────▶  window.__zcodeDesignRuntime（已装同版本则复用）
  run(command) ──────────────executeJavaScript───▶  set-mode / set-selection / set-element-style / set-element-text /
                                                     set-css-variables / set-variant / go-to-slide / locate-for-capture /
                                                     end-capture / read-info / read-document-token / dispose
  ipc-message(DesignEvents) ◀─sendToHost─ preload ◀─ window.postMessage({ __zcodeDesign: 1, events })
                                                     selection-changed / slide-changed / mode-changed
  ipc-message(DesignUndoShortcut) ◀─sendToHost─ preload keydown（capture、isTrusted、目标不是页面输入框）──▶ 宿主撤销 / 重做写回
```

- preload 只转发 `event.source === window`、带 `__zcodeDesign: 1`、`events` 为非空数组、序列化后不超过 256 KB 的消息
  （常量在 shared 的 `EMBEDDED_BROWSER_DESIGN_BRIDGE`，频道在 `EmbeddedBrowserWebviewChannels.DesignEvents`）。
  Coding Plan 的 webview 用另一个 preload，不受影响。
- 页面脚本照样能伪造这种消息：宿主侧 `parseDesignRuntimeEvents` / `parseDesignPageInfo` / `parseDesignPageSignals`
  逐字段校验，所有字符串和数组都按 `DESIGN_PAGE_LIMITS` 截断。伪造的选中最多变成用户看得见、能删的元素引用；
  伪造的源码路径最多让写回找不到元素（写回只改源码里与路径、标签、id、class、兄弟数都对得上的那个元素）。
- 运行时在设计工具显示、或人类 tab 开着点选时注入（普通网页退出点选即卸下）。`dom-ready` 后重新注入：
  同一页面刷新时宿主把模式、选中（按选择器）、CSS 变量预览、当前方案重新推给页面；换到另一个页面时退出点选、
  收起面板、清空选中、方案复位；单页应用换路由（pushState、前进后退）不重新注入，地址一变同样退出点选（取地址失败短暂退回 about:blank 不算换页）。迟到的旧页面注入结果丢弃。运行时卸下时调用 `dispose`：移除浮层、还原 CSS 变量预览、恢复所有方案可见。

## 三、入口与什么时候出现

- 设计工具只在设计稿页面（设计产物）出现：页面带 `<html data-zcode-design>`；或是本机页面（`file://`、`localhost`、`127.0.0.1`）
  且有 `:root` / `html` 规则里的 CSS 变量、`[data-variant]` 或 `section.slide`。普通网站很多也声明 `:root` 变量，所以这三项只对本机页面看。
- 人类 tab 的地址栏「选择元素」在任何页面上都是同一套点选（再点一次或页面里 Esc 退出），取代原来的元素选择器
  （11-06 产品决定：一个按钮一套逻辑；原来的选择器只给模型元素信息，新点选同样给，还能直接改）。
  选中后进完整视图、右上浮出「调整面板」；能不能改由页面决定：本机 HTML 文件在面板里改并写回源码，
  其他页面（普通网站、localhost 开发服务）面板只读，提示「这里只能查看，想改的话在输入框里告诉 Agent」。
- 设计稿页面另外出设计工具行（方案、翻页、调整面板开关）、深色点阵画布和舞台式去框；普通网页不出。
- Agent 的 Browser Use tab：仍是原来的元素选择器（点一个元素，输入框上方出「N 个网页元素」标签）。
- 只给人类用户打开的浏览器 tab 探测设计稿信号。

设计工具栏空间不足时，尺寸控件优先按完整宽度换到下一行；控件组本身比侧栏更宽时，内部控件继续换行，不能被挤到工具栏外；窄窗口验收须在侧栏可见时测量，零尺寸不能算作可达。

### Design 插件依赖（2026-11-09）

- Design 内置插件默认关闭；保留用户与项目已保存的显式选择。人类 Browser 的设计探测、工具行和点选仅在当前工作区有效启用 Design 后开放。
- 点击“选择元素”先读取当前工作区插件状态。Design 未安装或未启用时，显示共享确认窗：“需要 Design 插件”“选择元素需要安装并启用 Design 插件。请前往插件页面完成设置。”按钮为“取消”和“前往安装”。
- 确认只导航到 Design 的插件详情页，不自动安装、启用或进入点选。取消、Esc、关闭弹窗均留在浏览器；启用后再次点击即可使用。
- 查询失败显示读取失败提示，不当作插件缺失。查询/弹窗期间离开当前 tab、切换工作区或页面后，旧请求取消，不能打开新页面或启用旧页面的点选。安装/启停通过现有插件变更通道刷新；停用时卸下设计运行时并清理临时选择状态，保留已进输入框的引用。
- Agent Browser Use 的普通元素引用选择器和自由尺寸功能保持现有能力边界。Web/手机没有独立内置浏览器，不新增入口；共享弹窗支持深浅主题、中英文和窄屏。

```text
点击选择元素 → 当前工作区 CLI 插件状态
  ├─ 已启用 → 当前 tab 进入点选
  ├─ 未安装/未启用 → 安装提示 → 确认 → Design 插件详情页
  │                              └─ 取消 → 当前页面
  └─ 查询失败 → 显示失败提示，保持未选中
插件安装/启停 → 既有变更通知 → 工作区查询投影 → 设计运行时
```

验收：默认关闭、用户显式启用保持有效；未启用点击时不选中，取消/确认导航；详情页启用后回到原 Browser 可点选；停用后旧设计运行时卸下；加载中与切换目标时不使用旧结果。候选用例：`plugins/marketplace/manual-review/pending/plugin-design-builtin.test.ts`；既有 BU-E2E-021/022/023 显式准备 Design 已启用。

## 四、点选 = 元素 token 进输入框正文（像 Goal / Skill）

1. 点选时点一个元素 = 选中它（替换之前的选中）；Shift + 点击 = 加进 / 移出选中。点到按钮 / 链接里的文字或图标时选中按钮本身。
   页面上每个选中元素画选中框，多选时序号 1、2、3（选中顺序）贴在框左上角外侧、压在所有框上面；点选时按下鼠标不选页面文字（Shift + 点击不会选中一段文字）。面板「选中外层」把主选中换成它的外层。
2. 选中集合就是输入框正文里的元素 token（11-05 反馈，像选 Goal / Skill 一样）：每个选中元素是一个带指针图标的 token
   （`PromptMentionNode`，category `elements`），插在正文末尾，前后可以穿插文字、换行再改。发送时序列化成
   `[@元素名](zcode-element://引用 id)`，消息末尾的网页元素块里同一个元素带 `Reference: zcode-element://引用 id`，模型据此对上；
   历史消息里按同样的链接回显成元素 token。元素截图照常预上传、随消息发出，但不在附件行出缩略图（上传失败的照常显示）。
   token 与引用列表的同步只在 `ElementMentionSyncPlugin` 一处：引用多了插 token、少了删 token；用户在正文里删掉 token
   （程序化清空 / 发送后清空 / 历史回填不算）就移除这条引用并取消页面上的选中。
   点中就马上加引用（文字），截图在串行队列里补到同一条引用上（main 取帧可能要十几秒，窗口被遮挡时页面不出帧甚至等不到）；
   页面命令与截图都有上限（3 秒 / 20 秒），超时只带文字，任何一步卡住都不会挡住之后的点选；每份新文档换一代队列。
   随消息发出后只忘掉引用、选中留着，再点同一元素会重新引用。
3. 退出点选只收起选中框，已进输入框的引用留着；之后再点元素是新的选中。
4. 没有可接收的输入框（只读 pane、没有会话，或输入框不收引用）时照样能选中和改数值，提示一次「当前没有可接收的输入框」（每轮点选只弹一次：同一轮里写回、撤销引起的重读选中不再弹；退出点选、换页，或某次对账里引用全部被收下后复位）。

## 五、调整面板（悬浮在画布右上，改数值直接写回源文件）

1. 「调整面板」（11-06 由「设计」改名：「设计」读不懂）是悬浮在画布右上的卡片（`BrowserDesignInspector`，不撑满一列，高度随内容、超出时内部滚动，11-05 反馈），
   照 Figma 的 Design 面板：
   标题是元素类型（区块 / 文字 / 按钮…，多选「已选 N 个」），分区为 布局（W × H 只读、四边内边距）/ 外观（不透明度、圆角）/
   文字（字重、字号、对齐，按钮另有文字颜色）/ 填充（文字类元素是文字颜色，其余是背景）/ 变量；字段常显边框，悬停 / 聚焦时边框变色。点中元素时打开（关过也会重新打开；刚进点选、还没选中时不开），工具行按钮开关。面板只在完整视图里出：半屏里面板要出来（选中元素）就自动进完整视图，退出完整视图或退出点选时面板收起（不支持完整视图的端退回成面板盖在画布右侧）。面板开着时原型的大小和位置都不变（每种预设都按整页 Fit、在画布里居中），面板浮在画布右上；画布窄于 720px 时面板 256 → 192px，少挡原型。用户退出完整视图后在半屏里再选元素会再次进完整视图：半屏放不下原型 + 面板，又不缩小原型，面板只能在完整视图里用（11-05 用户反馈后的产品决定）。能写回是默认情况，面板不额外说明；只在写不回时写明原因。
   有选中时上半部分是元素属性，下半部分是页面变量；没有选中时只有页面变量。数值为主、不用滑杆（设计师对数字敏感）。
2. 元素属性（多选时显示最后点的那个元素的值，改动作用于全部选中元素）：
   - 数字框：输入后回车 / 失焦提交，↑↓ 微调（Shift × 10），拖左侧标签改值。
   - 颜色（填充、文字颜色、颜色变量）一行是「色块 | 十六进制 | 不透明度 %」：色块弹出页面 `:root` 颜色变量 + 自定义取色；
     不透明度 100% 写 `#RRGGBB`，否则写 `rgba()`。
   - 文字内容：单选、源码里该元素只含文字时，「文字」分区出文字框（回车或失焦提交）。
   - 页面上不能直接改（!3450 CR-01）：页面脚本能伪造发给宿主的消息，所以会引起写回的操作都在宿主侧——面板字段与
     preload 收下的真实按键；页面消息只有选中、翻页、退出点选。以前的双击改字、拖圆点改留白已去掉。
3. 写回：页面先立即预览，提交时写源文件：
   - 只对本机 HTML 文件（`file://…/*.html|htm`）。运行时给出元素从 `<html>` 往下每一级的标签、序号和兄弟数（不算运行时自己的节点），
     宿主用 parse5 解析源码沿同一路径走，每级标签与兄弟数都对得上、最后一级 id / class 也一样才算找到；
     然后只改这个元素开始标签里的 `style` 属性（合并改动的声明，没有就插入），文字只在源码里该元素只含文字时替换。
   - 页面变量改 `<style>` 里 `:root` / `html` 规则中那条声明的值；找不到或不止一处则不写。
   - 找不到（脚本生成的元素、页面不是本机文件、localhost 开发服务）时面板提示「这里只能查看，想改的话在输入框里告诉 Agent」
     （脚本生成的元素、非 UTF-8 文件各自带一句原因），数值框只读。
   - 只认能无损往返的 UTF-8 文件（含 BOM）：严格解码失败（GBK 等）就当读不了，面板只读并写明原因，文件一个字节都不动。
   - 改字的前后值都取 `textContent`（不取渲染后的 `innerText`，免得把 `text-transform`、空白折叠的结果写进源码）。
   - 文字框只在单选、且源码里该元素只含文字时出（带 span / strong 的元素样式可改、文字不能改）；换行写成文本换行而不是 `<br>`，写回后仍能再改。
     页面读回的文字截到 6000 字符，截到上限的元素不出文字框，免得用截断的值替换整段（!3450 CR-03）。
   - 样式合并：同名声明出现多次时（`color: red; color: blue`），第一处换成新值、其余同名的都去掉，免得后面的旧值继续生效。
     原来生效的声明带 `!important` 时，新值保留 `!important`（页面预览同样按原优先级设置）；面板不改优先级。
     相关的简写 / 分项带 `!important`（写 `background-color` 时 `background`、写 `padding` 时 `padding-top` 等）时，
     新值也带 `!important` 并挪到最后（同优先级后写的赢），预览按同一规则设成 important，源码与预览一致。
   - 写入带校验：`writeDesignSourceFile` 只在文件内容仍是读到的那份时写，否则放弃并提示（Agent 或别人刚改过）；读写报错（权限等）单独提示。
     「读、比较、写」在 Host 文件服务里按文件串行（同一进程内所有 tab 共用），两个 tab 同时提交时只有一个成功、另一个提示已改动。
   - 写回失败时页面撤回：元素按选中时记下的 style 属性与文字恢复，变量按源码当前值恢复，页面不留没写进源码的值。
   - 原地写（不走临时文件 + rename）：保留文件身份、权限与硬链接，Windows 上替换被占用的文件也不会失败；符号链接跟随到目标文件（与页面显示的内容一致）。
   - 自己写的改动不触发自动刷新：只认本 tab 还没收到变化事件的几次写入（写之前先记下，最多 4 次，没写进去的撤掉），
     文件内容与其中一次相同才跳过。连续写回时第一次的事件晚到、文件已是第二次的内容，也认作自己写的。
     对上第 i 次后，它和之前的几次都消费掉，之后外部改回已确认过的自写版本也照常刷新；读到别的内容（外部改过）就全部作废。
     同一次写入的重复通知按主 HTML 的指纹去重：主 HTML 的指纹是 mtime + size + 内容哈希（其他资源仍是 mtime + size），
     指纹没变就不刷新、也不再问是不是自写；同尺寸、mtime 又被保留的外部改动内容哈希不同，照常刷新。
     主 HTML 读不出文字时（超过写回上限、不是 UTF-8 等，`readDesignSourceFile` 拒读）退回只看 mtime + size：
     这类文件本来就不能写回，没有自写，只剩「同尺寸且 mtime 被保留的外部改动不刷新」这一处降级。
     别的 tab 打开同一文件照常刷新。选中和滚动位置不丢。
     合并的变化事件（同一防抖窗口改了多个文件）先重算全部资源的指纹，只有「变的只有主 HTML、且是本 tab 写的」才跳过。
   - 写回任务入队时记下页面代际（换页面就加一），每个异步步骤之后对不上就作废：不更新撤销栈、不动新页面。
   - 写回失败按这次任务实际读到的源码撤回页面（连续提交时不会把前一次已写成的结果也撤掉）；撤销记录里的写前文字同样取自源码。
4. 撤销：没有「重置」按钮。焦点在面板（字段里没有未提交的输入）或点选中的页面上时 Cmd/Ctrl + Z 撤销上一次写回、Cmd/Ctrl + Shift + Z 重做。
   页面里的按键由 guest preload 在隔离世界的 capture 阶段收（`DesignUndoShortcut`）：只认 `isTrusted` 的真实按键（页面 `dispatchEvent` 造不出来），
   用 `composedPath()` 判断按键当下的目标，落在页面输入框 / 可编辑区（含 open Shadow DOM 里的；closed shadow root 从外面看不到，按宿主元素算）就归页面撤销输入、不通知宿主；
   preload 只在主 frame 运行，iframe 里的按键不触发写回撤销（设计稿是单文档 HTML，不在 iframe 里改）。只通知不拦截，宿主只在设计稿页面点选时处理：
   文件仍是那次写入后的内容才还原，页面同步恢复；文件已被别的改动修改则提示并清空撤销栈。撤销栈每个 tab 一份，换页面清空。

```text
用户改数值 ──▶ 页面预览（set-element-style）
    │ 提交（回车 / 失焦 / 微调 / 松手）
    ▼
读源码 readDesignSourceFile ──▶ sourceEdit 按路径找元素 ──找不到──▶ 面板只读 + 提示
    │ 找到
    ▼
writeDesignSourceFile(expected = 读到的内容) ──文件变了──▶ 放弃 + 提示
    │ 写成
    ▼
撤销栈 push {文件, 写前, 写后, 页面前后样式}；自动刷新看到「内容 = 还没收到事件的某次写入」跳过
```

## 六、深色画布

- 设计稿页面在自由尺寸下，设备框外的画布是深色无限画布：`neutral-950` 底 + 16px 间距的浅色点阵（纯黑不透气，11-05 反馈）。
  普通网页仍是原来的 `background-alt`。
- 舞台式设计稿不框套框（11-05 体验反馈）：页面上有自带底色的画板（宽不到页面 70%、长宽都至少 160px，取最外层），且不在画板里、
  渲染出来的文字都是浅色（放到深色画布上看得清）、整页内容放得进视口（不需要滚动，否则透明后视口边界看不见、超出部分像被截断）时，运行时在预览里把 html / body / 撑满的外层容器设成透明（只注入样式，不动源码），
  宿主去掉视口外框与 webview 白底，画板直接落在画布上。落地页这类深色标题直接压在浅底上的页面不算，保持原样。
- 页面背景不可点选：html / body / 撑满的外层容器，以及舞台页里包着画板、自己没有底色的布局容器，点了不选中、悬停不画框；
  按住 Option / Alt 点仍能选中（改页面底色时用）。

## 七、方案与翻页

- 页面里有 `[data-variant]` 元素时显示方案下拉：「全部」+ 各方案名（按文档顺序去重）。选中某方案时只显示该方案的元素，
  并在 `<html>` 上设 `data-zcode-active-variant`；选「全部」还原。
- 页面里有 `section.slide` 时显示「‹ n / N ›」。翻页把对应 slide 滚到视口顶部；用户自己滚动时按视口中线所在的 slide 更新 n。

### 设计工具能力信号

内置浏览器的 ambient state（`<in-app-browser-context>`）由桌面 Host 在每次 sendText 时采集；手机远控同一会话时
也会采集到（main 侧 `listUserTabs` 按会话归属找 tab，不看 clientMode），Bot（飞书 / Lark / 微信 / Telegram / Discord / 企业微信，私聊与群聊）驱动同一会话时也一样，
但设计工具只能在桌面窗口里操作。所以只有输入来源是桌面（Host 按 clientMode 可信注入的 `inputOrigin: "desktop"`）
且不是 Bot 输入（命令信封 clientId 不是 `bot:` 前缀；Host 给所有 Bot 渠道的私聊与群聊输入都用 `bot:<botId>:<chatId>:<userId>`。Bot 输入的 inputOrigin 是埋点语义，也记为 desktop）时，CLI 才在这个块里多写一行
`- Design mode: available. …`，说明设计工具随设计稿页面出现（以及地址栏「选择元素」）、
点选的元素以网页元素引用带截图进来（Shift 多选）、属性面板的数值改动由 App 直接写进本机 HTML（Agent 改文件前要重新读）、方案 / 翻页。design 技能看到这一行才提示用户用，
没有（未开浏览器、手机远控、Bot 输入、来源未知）就退回「在浏览器里打开 + 文字描述」。不新增协议字段：老 CLI 的严格 schema 会拒绝未知字段，
`inputOrigin`、信封 `clientId` 都是既有字段（`botDeliveryTarget` 只有飞书 / Lark / 微信有，不能用来判断）。

## 八、不做

- 不自动发送；不做拖拽、图层、多人协作。
- localhost 开发服务（React 等组件源码）不直接写回，交给 Agent。
- Agent 打开 file:// 不在本期范围。

## 验收

- 只有地址栏「选择元素」一个入口，人类 tab 所有页面同一套点选。设计稿页面：深色点阵画布、设计工具行，选中后右上弹出调整面板、数值能改；
  普通网页：没有设计工具行，点选同样进输入框成 token（不再出原来的元素标签）、进完整视图，调整面板只读并说明交给 Agent。
- 设计稿页面点一个元素 → 输入框正文末尾出现一个元素 token（图标同「选择元素」），光标落在它后面，可以前后穿插文字；
  Shift + 点另一个 → 再多一个 token；再普通点第三个 → 只剩它的 token。
- 在正文里删掉 token → 对应引用移除、页面取消选中；撤销不会把已删引用的 token 带回来（引用的截图和页面信息已丢）；
  发送后 token 与引用一起清空，历史消息里同样显示成元素 token。
- 本机设计稿里选中标题把字号改成 46 → 页面立即变化、源文件里该标题的 `style` 多了 `font-size: 46px`、页面不刷新；
  在页面上（焦点不在页面输入框里）Cmd + Z → 源文件还原、页面还原；Cmd + Shift + Z 再改回；焦点在页面输入框里时 Cmd + Z 只撤页面输入。
  页面脚本伪造的消息改不了源文件。
- 页面变量改值 → 源文件 `:root` 里那条声明的值改变。脚本生成的元素 → 面板只读并提示。
- 三方案切换、3 页翻页正常。
