# 候选面板滚动位置

适用于输入框 `@`、`$`、`#`、`/` 触发的候选面板（共用 `MentionPanel`）。

## 规则

- 列表只在“选中项身份”变化时自动定位。身份由三部分组成：触发符与查询、选中序号、该选项的行 key。
  - 上下键移动选中项：定位，保证选中项在可视范围内。
  - 重新输入关键字：选中项回到首项，列表回到开头。
  - 前置分组加载完成，首项换成新分组的第一项：定位到首项并露出它的分组标题。
- 候选数据刷新但选中项身份不变（例如后台任务状态变化触发 `state:projects`）：不改动滚动位置。用户用滚轮翻到中段后，刷新后仍停在原处。
- 文件、任务两个分组在同一查询下刷新时，继续展示上一份成功结果，新结果回来后整体替换；不在刷新期间切回加载占位。首次加载、换查询、出错后仍显示加载占位。

## 验收

`packages/desktop/test/e2e/ui-shell/composer/chat-input-mention-navigation.test.ts`
中的 “keeps the wheel scroll position when candidates refresh” 用例：

1. 工作区放 40 个同前缀文件，输入 `@前缀` 得到长列表。
2. 真实滚轮滚到中段；用 `.zcodeignore` 去掉最后一个文件（让刷新结果和刷新前有差异），经 Host 广播 `state:projects`。
3. 等到列表少了这一条（证明新结果已替换上去），断言滚动位置不变、没有加载占位。
4. 连按 15 次下键，每次选中项都在视口内。
5. 再滚到中段并追加输入，列表回到开头、首项可见。
6. 改为只输入 `@`，各分组加载完成后首个分组标题与首项在视口内。

## 背景

反馈 ZCT-2122356778527907840（3.18.2）：滚轮翻到中段后列表被拉回开头。根因有两处：
面板曾在每次 `virtualRows` 换引用时滚回选中项；文件、任务分组在 `state:projects` 刷新时先清空成加载占位，列表高度塌缩。
