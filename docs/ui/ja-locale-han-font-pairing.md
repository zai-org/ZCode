# 日文界面下的中文字体配对

## 背景

无衬线正文字体栈是 `ui-sans-serif, system-ui, sans-serif`，中日韩汉字的字形由 `<html lang>` 决定
（`ZCodeIntlProvider` 跟随界面语言写入）。界面语言为日文时 `lang="ja-JP"`，日文汉字得到正确的日文字形。

## 问题（已修复）

macOS 日文界面下显示中文内容（中文消息、任务标题、文件名等）时，同一句话被两种字体混排：

- 日文字体里有的汉字用 Hiragino Kaku Gothic ProN。
- 日文字体里没有的简体字（这、问、题、请、说……）回退到苹方。

两种字体的字面大小和字重档位不同。`font-weight: 500` 时最明显：Hiragino 只有 W3 / W6，按 W3 渲染；
苹方有 Medium，按 Medium 渲染，同一句话里一部分字粗一部分字细，看起来像字号不一致。

`system-ui` 的回退链由系统决定，写在它后面的字体不会生效，所以不能靠在字体栈末尾追加字体解决。

## 规则

- 仅在 `:root:lang(ja)` 下生效，其他界面语言保持系统默认。
- 用带 `unicode-range` 的 `@font-face` 只接管汉字和 CJK 标点，西文仍走 SF，假名仍走系统日文字体：
  - `ZCode Han JP`：Hiragino Sans（W3 / W6），保证日文汉字仍是日文字形。
  - `ZCode Han SC`：Hiragino Sans GB（W3 / W6），补日文字体缺失的简体字。
- 两者同属 Hiragino 家族，字面大小和字重档位一致，混排时观感统一。
- 日文界面里显式标了其他语言的局部元素（`lang` 不是日文，例如语言选择列表里 `lang="zh-CN"` 的
  「简体中文」）恢复默认字体栈，由浏览器按元素自身的 `lang` 选字形。该规则放在 `@layer base`，
  不覆盖 `font-mono` 等工具类。
- 字重档位：只声明 400（W3）和 700（W6）两个字面，300 / 500 落到 W3，600 及以上落到 W6。
  修复前系统回退到的 Hiragino Kaku Gothic ProN 同样只有 W3 / W6，档位没有变化。
- 只引用系统本地字体（`local()`），不打包字体文件。Windows / Linux 上找不到这些字体时
  `@font-face` 自动失效，回到原有的系统回退，不改变现状。

## 不在范围内

- 韩文界面（`lang="ko"`）下的中文内容混排未处理。
- 英文、俄文界面在日文系统上的中文内容混排未处理：此时无法从 CSS 得知系统首选的 CJK 语言。

## 验收

- macOS 日文界面，文本「这个问题需要先复现再处理」在 400 / 500 / 600 三个字重下，
  汉字只使用 Hiragino Sans 与 Hiragino Sans GB，不出现苹方。
- 日文界面文案的假名和西文字体与修复前一致。
- 中文界面（`lang="zh-CN"`）渲染不变，汉字全部为苹方。
- 日文界面下 `lang="zh-CN"` 的元素汉字全部为苹方；同时带 `font-mono` 的元素仍是等宽字体。
