## Problem Statement

用户让 ZCode 处理文档时，官方文档插件已经存在，但执行转换和公式重算所需的 LibreOffice 不一定可用。
Agent 可能在任务中途临时寻找安装包、处理下载源和安装权限；已经下载的软件也可能因位置不一致而无法复用。
用户看到的是首次任务长时间没有结果、重复下载、安装失败，以及 Agent 改用用户已有办公软件造成的弹窗和工作干扰。

单纯提供一个下载地址还不够。用户需要知道准备进度和失败原因，并且之后的任务能稳定找到同一份可用程序。
安装成功也不能只以压缩包落盘或命令退出码为依据；文档转换、中文显示和表格重算必须经过实际验证。

## Solution

由 ZCode 管理一份独立的 LibreOffice，在本机后台准备，供本机文档任务共用。
首期只接管 LibreOffice；Python、Node 库及其他依赖仍按现有机制处理，后续再扩展。

- 自动预装默认开启。App 启动后检查当前版本要求的资源，已就绪则复用，未就绪则从指定 CDN 后台准备。
  普通聊天不等待下载，不依赖用户先调用某个 Skill，也不以单个插件的启停作为下载条件。
- 准备在后台静默执行，不弹出任何提示，帮助菜单项也不显示状态。用户打开“预装工具”对话框查看状态和失败原因。
- 在右上角帮助菜单的“资源管理器”之后新增“预装工具”。点击打开“预装工具”对话框，集中展示自动预装开关、
  LibreOffice 版本、状态、进度、失败原因和操作按钮。常规设置页不重复放这个开关。
- 自动预装开关是本机持久设置。关闭后不再自动发起准备，但当前下载继续；立即停止当前操作使用“取消下载”。
  已安装程序保留并继续可用，关闭开关时仍可手动下载或重试，手动操作不改变开关。
- 对话框提供“删除”，用于回收磁盘。新目标版本就绪后，下次启动删除旧版本。
- ZCode 优先使用自己管理、验证过的版本。受管版本未就绪时，可以使用系统已装的 LibreOffice（不限版本，含开发版），
  并告诉用户系统版本及受管版本未使用的原因。
  准备过程无需管理员权限，不修改用户的办公软件安装和配置。
- 文档任务可以正常开始。到必须使用 LibreOffice 的步骤，受管版本和可用的系统版本都没有时，
  Agent 说明预装未就绪及原因，保留已有成果，由用户选择等待或按 setup.md 安装。
  桌面有发布目标时，可在“帮助 → 预装工具”查看准确进度，避免 Agent 与后台重复下载。准备完成后由用户让 Agent 继续。首版不增加任务自动暂停、自动恢复或自动重发机制。
- 准备失败时在对话框中显示原因并允许重试，不跳过必要检查后宣称任务完成。
- 首版目标版本固定，由 ZCode 发布时确定。资源仍独立存放在 CDN，不打入主安装包；不独立追踪最新版本或定时自动升级。
- 未完成的下载在取消或退出后不续传，下次重新下载；完整且可用的安装直接复用。
- 工程实施方负责整理和验证各平台资源包，资源发布方负责部署 CDN 并提供下载地址。

```mermaid
flowchart TD
    A[App 启动且自动预装开启] --> B[本机资源服务检查目标版本]
    M[用户在对话框中下载或重试] --> B
    B --> C{资源是否已就绪}
    C -->|是| R[复用已验证程序]
    C -->|否| D[后台静默下载、校验、解压、运行检查]
    D -->|成功| R
    D -->|失败| E[对话框显示原因并允许重试]
    D -->|取消或退出| X[不发布半成品，下次重新下载]
    T[文档任务需要 LibreOffice] --> Q{受管版本是否就绪}
    Q -->|是| U[使用 ZCode 管理的程序]
    Q -->|否| S{系统是否有 LibreOffice（不限版本）}
    S -->|是| SU[使用系统版本并说明]
    S -->|否| W[说明原因并保留成果，由用户选择等待或安装]
    W --> V[准备好后由用户要求继续]
    V --> Q
```

## 决策记录

| #   | 问题                                 | 决定                                                                                                                                                                                                    |
| --- | ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | 受管版本未就绪，系统已装 LibreOffice | 回退使用系统版本。系统旧版和开发版均可使用，并使用独立配置。Agent 说明系统版本及受管失败原因。受管版本就绪后，始终优先使用受管版本。                                                                    |
| 2   | LibreOffice 配置目录                 | 使用 ZCode 专用配置模板，模板内含重算宏和字体替换设置。每次调用复制到独立临时目录，调用结束删除。受管版本和系统版本都按这个方式调用。不读写用户默认配置。                                               |
| 3   | 中文字体                             | 少量中文字体放进受管 LibreOffice 自己的字体目录，不装进系统字体目录。文档指定的字体在系统中存在时，使用系统字体；不存在时，用随包中文字体替代。                                                         |
| 4   | 插件脚本和说明的改动位置             | 先改上游插件仓库，再按同步流程导入并升版。不在本仓库保留本地补丁。                                                                                                                                      |
| 5   | 正式版、预览版、开发版的安装位置     | 按发布版本分别安装。各发布版本不共享安装目录和在途操作。                                                                                                                                                |
| 6   | 删除和清理                           | 对话框提供“删除”，有调用正在使用时不允许删除。新目标版本就绪后，下次启动删除旧版本。“清除所有数据”不删除受管资源；资源管理器存储页不提供清理。启动时清理上次中断留下的临时安装目录。                    |
| 7   | Agent 能说明的状态                   | 只区分“就绪”和“未就绪”。未就绪时说明原因；桌面有资源目标时提示到“帮助 → 预装工具”查看准确状态，并由用户选择等待或安装。                                                                                 |
| 8   | 主动提示                             | 不做。准备在后台静默执行；开始和失败都不弹 Toast，帮助菜单项不显示状态或标记。用户打开“预装工具”查看。                                                                                                  |
| 9   | 多窗口                               | ZCode 只有一个应用窗口，本功能不考虑多窗口。                                                                                                                                                            |
| 10  | 开源版                               | 本期不考虑开源版的资源分发与开关。                                                                                                                                                                      |
| 11  | 管理界面                             | 采用方案 A“工具卡片”：主窗口内的对话框，开关在上，每个工具一张卡片。系统已装的 LibreOffice 不在对话框中显示。                                                                                           |
| 12  | 升级时的显示与使用                   | 只显示当前目标版本的状态。旧受管版本不显示，也不再给 Agent 使用；新版本就绪后在下次启动时删除。                                                                                                         |
| 13  | 预装服务所在进程                     | 新建独立的常驻“预装工具进程”。Main 在 App 启动时拉起它、在 App 退出时通知收尾，并在窗口与它之间转发消息，不保存预装状态。进程意外退出后由 Main 重新拉起；新进程清理临时目录、恢复状态，不自动重新下载。 |
| 14  | 资源包来源                           | 使用 LibreOffice 官方发布的二进制，并核对官方签名。发布前把各平台官方安装包转换为统一的归档格式，同时加入随包中文字体。不自行编译。资源包放在 ZCode CDN，运行时不从公共镜像下载。                       |
| 15  | 验证范围                             | 开发阶段只在本机 macOS arm64 上充分验证。其他五个目标的资源包由转换工具产出并做结构检查；实际运行验证之后由人工完成或另起任务。完成前不宣称全平台完成。                                                 |

## User Stories

### 自动准备和手动控制

1. 作为首次使用桌面端的用户，我希望默认自动准备 LibreOffice，以便开始文档任务前就有机会完成环境准备。
2. 作为桌面端用户，我希望准备在后台静默进行，以便普通聊天和其他工作不被下载或提示打断。
3. 作为仅使用编码功能的用户，我希望能关闭自动预装，以便控制额外下载和磁盘占用。
4. 作为关闭自动预装的用户，我希望下次启动 App 时不再自动发起准备，以便我的选择持续生效。
5. 作为关闭自动预装的用户，我希望仍能手动下载 LibreOffice，以便偶尔需要文档能力时按需准备。
6. 作为手动下载的用户，我希望操作不自动打开预装开关，以便一次性操作不会改变长期偏好。
7. 作为已有可用安装的用户，我希望关闭自动预装后仍能使用它，以便已有任务不因关闭开关而失去工具。
8. 作为正在下载的用户，我希望关闭自动预装只影响后续自动准备，以便长期偏好与当前操作分别控制。
9. 作为正在下载的用户，我希望能单独取消当前下载，以便立即停止这一次准备。
10. 作为取消下载的用户，我希望取消不改变自动预装开关，以便下次启动仍按我保存的偏好处理。
11. 作为重新打开 App 的用户，我希望未完成的下载重新开始、已完成的安装直接复用，以便状态和下载行为清楚可见。
12. 作为想回收磁盘的用户，我希望在预装工具对话框删除已安装的 LibreOffice，以便不必自己寻找安装目录。
13. 作为升级 App 的用户，我希望旧版本资源在新版本就绪后自动清理，以便磁盘占用不随升级累积。

### 统一入口和清楚反馈

14. 作为桌面端用户，我希望在帮助菜单找到“预装工具”，以便快速查看文档环境是否可用。
15. 作为用户，我希望自动预装开关和安装信息在同一个对话框里，以便不必在帮助菜单和设置页之间来回寻找。
16. 作为用户，我希望看到 LibreOffice 的当前状态和版本，以便知道当前能否使用。
17. 作为等待准备的用户，我希望看到下载进度和校验、解压等阶段，以便知道程序仍在正常工作。
18. 作为遇到失败的用户，我希望看到能理解的失败原因和重试入口，以便知道下一步如何处理。
19. 作为用户，我希望切换工作区或关闭对话框不会中断后台准备，以便查看行为不影响安装。
20. 作为中英文用户，我希望菜单、状态、进度和错误都有对应语言，以便理解工具准备情况。
21. 作为深色或浅色主题用户，我希望对话框清晰可读，以便准确识别状态和可用操作。
22. 作为使用较小桌面窗口或键盘操作的用户，我希望能够打开、浏览和关闭对话框并操作按钮，以便不受窗口尺寸或输入方式限制。

### 任务使用和已有成果

23. 作为文档任务用户，我希望 Agent 优先使用 ZCode 管理的 LibreOffice，以便不受系统安装位置和版本差异影响。
24. 作为自己已装 LibreOffice 的用户，我希望 ZCode 的版本未就绪时能先用我已装的版本，并告诉我用的是哪一份，以便任务不必等待下载。
25. 作为用户，我希望新任务和不同工作区复用同一份本机安装，以便不重复下载相同资源。
26. 作为已有会话的用户，我希望安装完成后在原会话说“继续”就能使用工具，以便不用重开会话。
27. 作为环境尚未就绪的用户，我希望 Agent 说明工具未就绪并告诉我去哪里查看进度，以便不会把环境问题误解成模型一直在思考。
28. 作为文档任务用户，我希望未就绪时已经生成的文件得到保留，以便继续时可以沿用已有成果。
29. 作为用户，我希望安装完成后由我决定何时继续原任务，以便后台事件不会擅自重发请求或执行文档操作。
30. 作为正在使用办公软件的用户，我希望 ZCode 不因自己的环境缺失而自动打开或关闭我的办公软件，以便当前工作不被打断。
31. 作为接收文档的用户，我希望失败的转换或检查被明确报告，以便不会收到未经必要验证却被称为完成的文件。
32. 作为使用插件的用户，我希望单个插件的启停不会导致共享 LibreOffice 被重复安装或删除，以便各插件可以稳定共用环境。

### 文档效果和平台兼容

33. 作为 Word 文档用户，我希望本机预装程序能完成文档转 PDF，以便检查实际分页和排版。
34. 作为演示文稿用户，我希望本机预装程序能完成 PPT 转换，以便检查每页内容是否正常。
35. 作为电子表格用户，我希望现有公式重算流程能使用预装程序，以便得到实际计算结果并发现公式错误。
36. 作为中文文档用户，我希望转换后的中文可见且正确；文档指定的字体电脑上没有时，用随包中文字体替代，以便不出现缺字方框。
37. 作为 Windows、macOS 或 Linux 用户，我希望获得与自己的系统和处理器匹配的资源，以便不会下载一个无法运行的包。
38. 作为没有管理员权限的用户，我希望能在自己的用户目录完成准备，以便不必求助管理员。
39. 作为已经安装 LibreOffice 的用户，我希望 ZCode 不修改或移除我的系统版本及其配置，以便原有工作习惯不受影响。
40. 作为通过桌面打开远端工作区的用户，我希望“预装工具”明确显示它管理的是本机，以便不会误以为远端也已经安装。
41. 作为同时处理多个文档任务的用户，我希望各次调用不会互相污染临时文件或程序配置，以便结果稳定且可追踪。
42. 作为同时安装正式版和预览版的用户，我希望两个版本的准备互不干扰，以便不会因为同时下载而装坏。

### 失败恢复、版本和资源交付

43. 作为用户，我希望多个任务同时需要资源或重复点击下载时共用一次准备，以便不同时下载多份相同的包。
44. 作为用户，我希望下载中断、内容损坏或运行检查失败时不会发布半成品，以便“已就绪”状态可信。
45. 作为已有完整安装的用户，我希望失败的新准备不会损坏现有安装，以便保留恢复和继续工作的基础。
46. 作为用户，我希望不会在后台突然升级到未经当前 App 验证的工具版本，以便文档效果更稳定。
47. 作为维护者，我希望资源包有明确版本、适用平台、校验信息和来源记录，以便定位下载与兼容问题。
48. 作为资源发布方，我希望收到工程实施方验证过的资源包和发布信息，以便按确定内容部署 CDN。
49. 作为工程实施者，我希望每个平台的资源都经过实际文档处理验收，以便不会把“下载成功”误报为“功能已完成”。
